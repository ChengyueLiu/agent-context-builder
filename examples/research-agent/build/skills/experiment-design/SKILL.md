# 实验设计

## 目的

把论断清单变成可执行的实验方案，在跑实验之前就定下什么结果算支撑。

## 具体做法

1. 论断清单逐条列出需要的证据。
2. 为每条证据设计实验：数据、基线、指标、对照、消融。
3. 写明停止条件和统计检验方法。
4. 估算算力和时间，超出预算的标出来交用户决定。

## 产出什么

实验方案，交用户拍板后进入实验执行。

## 合格标准

- 每条论断都有对应的对照组和必要的消融。
- 写明评测指标、数据划分和统计检验方法。
- 写明停止条件：什么结果算支撑、什么算不支撑，在跑实验之前定下。

## 容易出的错

- 不要只在一个数据集上评测：审稿人会质疑泛化性。至少用两个公认的基准。
- 基线用原论文推荐的超参，或者给基线同样的调参预算：否则提升可能只是调参带来的。
- 测试集只在最后用一次：反复看测试集，它就变成了验证集。

## 范例

论断：方法 A 在长文本上比基线 B 更稳定。

- 数据：LongBench 与 SCROLLS 两个基准。
- 基线：B 用原论文的超参；另给 A 和 B 相同的调参预算各跑一次。
- 指标：各长度区间的准确率及其方差，5 个随机种子。
- 支撑的标准：长度超过 8k 的区间，A 的方差显著小于 B（配对检验 p < 0.05）。
- 不支撑的标准：任一基准上差异不显著。

## 产出物

- **实验方案**（`outputs/design/plan.md`）：每条论断对应的实验，跑之前定好什么结果算支撑。什么时候写：实验设计这一步。写新版本，旧版保留。用户确认后才算数。
